# 空格听写（Hold to Dictate）

在 DeepSeek Harness（DSH）的聊天窗口里，**按住空格说话，松开后把识别结果填入草稿**。也可以为当前会话开启自动发送。插件复用 DSH 官方语音输入，不自带语音模型。

## 安装

1. 打开本仓库的 **Releases**，在 **Assets** 中下载 `local-dsh-hold-to-dictate-1.1.3.tgz`，不要解压。请选择插件的 `.tgz` 文件，不要选 GitHub 自动生成的 **Source code**。如果还没发布 Release，可以向维护者索取 `.tgz` 安装包。
2. 在 DSH 左侧打开 **插件 → 添加插件**，粘贴 `.tgz` 文件的完整本地路径，安装并启用「空格听写」。如果已安装旧版且提示同名插件已存在，先卸载旧版「空格听写」，再安装新版；不用卸载官方语音输入。
3. 在 **插件 → 实验性插件 → 更多** 中启用官方 **语音输入**（`@deepseek-ai/dsh-experimental-voice-input-bundle`），按提示准备识别模型。先手点一次聊天框旁的麦克风，授予权限并确认说话能转成文字。

## 使用

1. 打开聊天，点一下聊天内容的空白处，让焦点离开输入框和按钮。
2. 按住 **空格键**，看到开始录音后说话。
3. **松开空格键**，等文字填入草稿。确认无误后，点击发送。

光标在输入框里时，空格仍用于正常打字。录音中按 `Esc` 或切走窗口会取消；尚未开始录音就松开也会取消。

### 听写后自动发送

输入框工具栏里的 **听写后自动发送** 开关默认关闭。开启后，如果录音前草稿为空且没有附件，松开空格、识别成功后会自动提交。已有草稿或附件、识别失败、中途编辑或切换会话，以及识别结果以 `/` 开头时，都不会自动提交。

开关只对当前会话生效，**新会话始终默认关闭**。手点官方麦克风录音不受这个开关影响。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 按空格没反应 | 先确认焦点不在输入框或按钮上，再确认「空格听写」已启用、官方麦克风能正常听写。 |
| 麦克风没有出字 | 先检查 DSH 官方语音输入的模型是否准备完成、麦克风是否已授权。 |
| 更新后没看到开关 | 完全退出后重开 DSH NEXT，再进入聊天。开关在输入框工具栏、模型选择器左侧。 |
| 只想恢复原来的听写方式 | 禁用「空格听写」即可；官方麦克风仍可手动使用。 |

## 兼容性与隐私

- 按 **DSH `0.2.2-rc.5`** 的听写界面适配，支持简体中文和英文界面的按钮；其他版本未验证。
- 插件不直接读取麦克风音频，也不调用额外的转写服务。音频由你启用的 DSH 官方语音输入处理。安装包不包含 DSH 配置、凭据、聊天记录或模型。

开发回归检查：在已安装 Playwright 的 Python 环境运行 `python check.py <Chrome 可执行文件路径>`。
